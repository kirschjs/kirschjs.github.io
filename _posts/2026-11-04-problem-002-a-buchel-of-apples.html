At a dinner table, I once claimed that with refined 3D printers, interconnected cell phones, and now a Star-Trek-"Computer" incarnation, the replicator age is close, i.e., the things consumable and desirable by individuals and which do not exceed a certain size, can be produced in any country, city, village. We are only limited by not combining those things which surround us even in so-called poor countries.

This project is poor Johannes’ version of this very special blind man deriving pleasure from turning some numbers into others by orchestrating an army of computers (not in the Butlerian Jihadi’s sense). And envious he looks abroad without seeing all the computational wealth surrounding him. Make him see and walk.

Your mission, if you...

Your university/school has equipped rooms with multiple (apple) desktop computers which are unused when there are no classes. During this idle time, these clusters of c/gpus shall be used for scientific tasks. Given the limitations placed by the start of the next class, the relatively slow connection between the computing nodes, and all issues related to the closedness of iOS, realize a framework which would allow me to distribute \(\mathcal{O}(10^4)\) runs of a single sequence of codes (FORTRAN, python, &c.) with typical runtime \(\tau=\mathcal{O}(10m)\) onto the classroom. The framework should be controllable from my Linux terminal, and the results of each client run should be stored there temporarily before sending them to me.

If you plan to engage in this problem, contact me for sample code.

Make it so?

  • Flow diagram of the computation starting from its trigger on the Linux terminal to the final result collection

  • Practical implementation respecting the boundary conditions, i.e., runtime estimate and possible job rejection

  • An alternative suggestion on how to utilize the dormant computing resources linked by the university network, or make an argument that would render the enterprise non-sense, carbon-emmision driving, vain, technically harmful for architectures not designed to run HPC, &c.
